# Private artifact retention

The owner approved 90-day private deck retention with fresh download links and
no new web service. Architecture review advanced the scoped change on repository
source evidence; that approval is not evidence of deployment or runtime checks.

## Storage and access

The existing `agent-pipe` bucket uses separate lifecycle prefixes:

| Prefix | Object expiration | Incomplete multipart upload cleanup |
| --- | --- | --- |
| `deliveries/` | 1 day, unchanged | 1 day after initiation |
| `presentations/` | 90 days | 1 day after initiation |

Store only approved non-secret artifacts. Use unique presentation object keys
rather than overwriting earlier decks. Retention is a lifecycle expiration policy,
not an immutable retention lock or a promise of deletion at an exact instant.
This root does not configure versioning for this bucket; unexpected enabled or
suspended versioning requires review of noncurrent-version retention before use.

Public access blocking, AES256 encryption, bucket-owner-enforced ownership and
`prevent_destroy` remain unchanged. The managed MCP role gains only
`s3:PutObject` on `presentations/*`; its delivery upload permission, existing read
baseline, trust and state-object read deny remain unchanged. This is not a
write-only role or a new public-access grant.

Issue a fresh short-lived signed download link when an authorized user needs a
retained deck. Object retention does not extend link lifetime. Do not commit
signed URLs, secrets, state or sensitive plans to this public repository.

## Ownership and rollout gates

`tfroot-aws` owns the bucket lifecycle and IAM policy. Artifact producers and
approved transfer profiles must select and permit `presentations/`; this root
change alone does not configure those consumers or prove end-to-end delivery.

1. Review the scoped branch before opening a PR. Use PR CI as authoritative
   validation, not local OpenTofu or Makefile commands. Expect only the existing
   lifecycle configuration and artifact-upload inline policy to change; stop on
   bucket replacement or unrelated changes. Inspect sanitized evidence only.
2. Retain existing merge and environment approvals for the main apply path.
   A source approval does not authorize workflow dispatch, apply or publication.
3. Before enabling retained-deck delivery, separately authorize and verify the
   producer/profile configuration, effective private upload and fresh-link
   download, the unchanged delivery rule, and the presentation lifecycle rule.
   Check that anonymous access remains blocked. Do not wait 90 days or claim
   that a configuration check proves physical expiration occurred.

The reusable workflow is owned by `shared-workflows`; the runner and canonical
pre-commit configuration are owned by `images/tfroot-runner`. This feature changes
neither. Provider constraints, outputs and generated resource inventory are
unchanged. `README.md` is replace-generated by `.terraform-docs.yml`; this
standalone document is maintained separately and requires no README hand edit.
